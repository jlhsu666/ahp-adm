# AHP 問卷與分析系統（GitHub 部署版）

一個研究者可以自己部署、自己管資料的層級分析法（AHP）問卷系統：
填答者線上做成對比較 → 資料寫入研究者自己的 Google Sheets →
研究者在管理後台看紀錄、下載 raw data、一鍵產生論文第四章格式的分析報告。

**不同研究者 = 各自部署一份。** 每個人 fork 這個 repo、接自己的 Sheet、
設自己的後台密碼，資料互不相通，不用共用同一個後台、不用交出 Google 密碼。

## 一、5 分鐘部署（GitHub Pages + Google Sheets）

### 1. 上 GitHub 並開 Pages

1. 把這個資料夾推到一個 GitHub repo（公開或私人皆可；私人 repo 的 Pages
   仍需依 GitHub 方案而定，公開 repo 最簡單）。
2. repo → Settings → Pages → Build and deployment → Source 選
   Deploy from a branch，Branch 選 `main`、資料夾選 `/(root)`，存檔。
3. 等幾分鐘，Pages 會給你一個 `https://<帳號>.github.io/<repo>/` 網址，
   用瀏覽器打開，看到問卷頁就是成功（此時還是本機模式）。

### 2. 建 Google Sheets + Apps Script（資料庫）

1. 在 Google Drive 新建一個試算表，名稱例如 `AHP 問卷資料`。
2. 在試算表裡點「擴充功能 → Apps Script」。
3. 把 `apps-script/Code.gs` 整份貼上，存檔（Ctrl+S）。
4. （刪除保護用，建議做）左邊齒輪「專案設定 → 指令碼屬性」新增一筆：
   屬性 `ADMIN_CODE`，值與下一步網站的後台密碼相同。不設的話，
   後台刪除 Sheet 資料會被拒絕（這是故意的，預設不給刪）。
5. 右上「部署 → 新增部署 → 類型：網頁應用程式」：
   - 執行身分：**我**
   - 存取權：**任何人**（這樣填答者的瀏覽器才能寫入；網址本身不公開宣傳即可）
   - 按「部署」，複製網頁應用程式網址（以 `https://script.google.com/macros/s/.../exec` 開頭）。

### 3. 把 Sheet 接回網站

1. 打開 `config.js`，把 `appsScriptUrl` 改成上一步複製的網址。
2. 把 `adminCode` 改成自己的後台密碼（不要用預設值）。
3. 把改好的 `config.js` 推上 GitHub，等 Pages 更新後再打開網站，
   填答頁上方應不再出現「本機模式」提醒。
4. 自己先填一份測試問卷，到試算表確認出現「填答原始資料」與
   「個人權重結果」兩張工作表，再到網站後台用密碼登入、選
   「Google Sheets」來源，確認讀得到這筆。

> 沒有 Sheet 也能先測試：`appsScriptUrl` 留空就是本機模式，
> 填答存在填答者瀏覽器 localStorage。正式收案前請務必先接好 Sheet 再發連結，
> 否則研究者收不到分散在各台瀏覽器的資料。

## 二、研究者自訂研究架構

改 `config.js` 即可，不用改程式：

| 欄位 | 說明 |
|---|---|
| `studyTitle` / `studySubtitle` | 問卷標題與副標題 |
| `dimensions` | 主構面陣列，每個構面有 `name` 與 `items`（子構面陣列）；構面數、子構面數都可增減，成對比較題數會自動重算 |
| `groupLabel` / `groupOptions` | 分組欄位名稱與選項（論文是「任教班別：集中式特教班／不分類資源班」） |
| `backgroundFields` | 背景資料欄位（論文附錄：性別、年齡、教育程度、服務年資）；不需要的整筆刪掉 |
| `genericDimensions` | 通用範本，後台「研究設定」可一鍵載入 |

更順的做法：先在網站後台「研究設定」改好架構，按「下載新的 config.js」，
覆蓋 repo 裡的 `config.js` 再推上 GitHub。**注意：研究架構改變後，
舊架構的資料不會跟新架構混算**，分析報告會自動排除架構不同的筆數並提示。

預設架構是論文《應用層級分析法探討特教教師使用資訊融入教學之考量因素》
的 4 主構面 × 16 子構面，可直接沿用或改名。

## 三、使用流程

### 填答者

1. 開啟問卷連結，填基本資料（匿名編號、分組、背景）。
2. 依 Saaty 1–9 量尺逐題做成對比較（1 同等、3 稍微、5 頗為、7 極度、9 絕對；
   2、4、6、8 為中間值；系統自動取倒數）。每題改用大按鈕步進滑桿作答：
   拖動滑桿或按兩邊的加減鈕，中央為同等，偏左表示左項較重要，偏右表示右項較重要，
   大字顯示目前判斷；完全沒動過的題目會被視為未填，計算前會提醒補填。
   相依第二階段的滑桿只停在 1、3、5、7、9（不使用中間值）。
3. 按「計算我的個人結果」看自己的權重與 C.I.／C.R.，確認後送出。
4. 送出後會寫入 Google Sheets（或本機模式下存在瀏覽器並可下載 JSON 寄給研究者）。

### 研究者（管理後台）

後台入口在網站上方「管理後台」，輸入 `config.js` 的密碼進入。

- **資料來源**：本機紀錄／Google Sheets／匯入檔案（本系統 JSON 或含
  `comparisons_json` 的 CSV）。若 Sheets 跨網域讀取被瀏覽器擋下，
  可改用「Sheet → 檔案 → 下載 → CSV」再匯入，分析功能完全相同。
- **填答紀錄**：篩分組、篩有效／無效、搜尋編號；點「查看」看該筆 5 張矩陣、
  權重、C.I.／C.R.；可刪除（Sheets 刪除需先設定 ADMIN_CODE）。
- **下載 raw data**：
  - `ahp_raw_data.csv`：一列一筆，含編號、時間、分組、背景、全部成對比較原始值
    （正值表示左項較重要幾倍，負值表示右項較重要幾倍）。
  - `ahp_weights.csv`：一列一筆，含主構面權重、各構面區域權重、全域權重、C.I.／C.R. 與是否有效。
  - `ahp_records.json`：完整原始資料（含研究架構快照與比較值），供備份與再分析。
- **分析報告**：見下一節。可用「載入示範資料」先看報告長相
  （8 筆合成資料，最後一筆刻意不一致，示範無效排除效果；示範資料非真實問卷）。
- **下載 Word 報告（第四章格式）**：報告頁另有「下載 Word 報告（第四章格式）」，
  產出真正的 .docx 檔（不需外掛套件，直接在瀏覽器產生）。格式依 HiTeach 論文
  第四章「研究對象與結果分析」慣例：章標題「第四章 研究結果與分析」置中、
  節標題（第一節、第二節……）置中、內文標楷體 12pt 行距 1.5 倍首行縮排 2 字；
  表題在表上方（「表 4.1 標題」，章內連續編號、標號與標題間有空格），不加資料來源註；
  表格內文一律 12pt；節標題一律「第X節」格式；附錄（構面與指標定義）不進 Word，僅見於網站報告；
  逐人權重表含平均與排行兩列、全域表含區域權重／全域權重／排序，權重皆取小數第三位；
  研究者在報告頁填的「研究者解讀」會一併寫入 Word。長條圖不進 Word，
  圖表請見網站報告，Word 版以各表之權重與排序呈現全部數據。

## 四、分析報告格式（對照論文第四章）

後台「分析報告」→ 勾選「只納入有效問卷」（預設，論文做法）→「產生分析報告」。
報告結構與論文第四章一一對應：

1. **樣本總覽**：分組與背景分布。
2. **第一節 全體問卷結果**：主構面逐人權重表（含每人 C.I.／C.R.）＋平均＋排行；
   每個構面各一張子構面逐人表＋平均＋排行；全域權重表（區域權重、全域權重、排序）
   ＋ 16 項橫條排行圖（論文圖 5 格式）。
3. **第二節起 各分組問卷結果**：與全體同格式，每組一節（論文第二、三節格式）。
4. **最後一節 各分組結果比對**：各組第一名對照、16 項全域權重與排行對照表、
   權重差（兩組時）、分組並排橫條比較圖（論文圖 8 格式）。
5. 每節下方都有「研究者解讀」空白欄，研究者打好詮釋後，列印／下載的報告
   會一併印出。報告可「列印／存成 PDF」或「下載報告 HTML」交給指導教授或放進論文附錄草稿。

## 五、計算方法（與論文第三章一致）

- 成對比較矩陣為正倒數矩陣，對角線為 1，`a_ji = 1 / a_ij`。
- 權重取主特徵向量（冪迭代法），正規化使總和為 1。
- `λmax = mean((A·w)_i / w_i)`；`C.I. = (λmax − n) / (n − 1)`；
  `C.R. = C.I. / R.I.`；R.I. 採 Saaty 表（n=3 為 0.58、n=4 為 0.90、n=5 為 1.12，
  餘見 `assets/ahp.js` 的 RI 表）。
- **C.R. ≦ 0.1 為有效**；一份問卷 5 張矩陣（1 張主構面＋4 張子構面）須全數通過才算有效。
- **多人彙總採論文第四章做法**：先算每位受訪者的區域權重，再取算術平均；
  全域權重 = 主構面平均權重 × 子構面平均區域權重。報告數值四捨五入至小數第三位，
  加總可能差 0.001；有效判定以未四捨五入值計算。

## 六、資料字典

### 填答紀錄（JSON / CSV 欄位）

| 欄位 | 說明 |
|---|---|
| `id` | 填答編號（自填或系統編號），匿名，請勿填真實姓名 |
| `submitted_at` | 填答時間（ISO 8601） |
| `group` | 分組（`groupLabel` 的值） |
| `background` | 背景資料物件，鍵為 `backgroundFields` 的 `key` |
| `comparisons.main` | 主構面比較值，鍵為 `"i-j"`（i、j 為構面序號），值為帶號 Saaty 值 |
| `comparisons.sub0`… | 各構面子構面比較值，鍵同上 |
| `structure` | 填答當時的研究架構快照（構面與子構面名稱），架構改變後靠它分流 |
| `demo` | 是否為示範資料 |

比較值編碼：`3` 表示左項比右項稍微重要（3 倍），`-3` 表示右項比左項稍微重要（3 倍），`1` 表示同等重要。

### Sheet 工作表

| 工作表 | 內容 |
|---|---|
| 填答原始資料 | 同上，一列一筆；最後一欄 `comparisons_json` 為完整填答 JSON，**勿刪**，後台讀回靠它 |
| 個人權重結果 | 一列一筆：主構面權重、每構面 C.I.／C.R.、區域權重、全域權重、是否有效 |

## 七、限制與安全提醒（請先看再收案）

- **後台密碼不是真正的帳號驗證**：它寫在 `config.js` 裡，看得到原始碼的人
  就看得到密碼，所以它只是防誤觸的門檻。請一律匿名填答，不要收集姓名、
  電話、電子郵件；高度敏感研究請把 repo 設為私人、並另外評估是否適合用此架構。
- **Apps Script 部署為「任何人」**：任何拿到網址的人理論上可寫入你的 Sheet，
  因此網址只發給填答者、不要公開貼在社群；定期檢查 Sheet 是否有異常列。
- **本系統不做登入去重**：同一人重複填答會算成多筆，研究者請以編號核對，
  或在發放時一人發一個編號。
- **不支援離線同步**：本機模式的資料只在該台瀏覽器，正式收案務必接好 Sheets。
- 純前端＋Apps Script，無伺服器費用；GitHub Pages 與 Google Sheets 免費額度
  依各平台當時方案為準。

## 八、通用版（v2）新增功能

v1 只適合「4 構面 × 4 指標、單一分組」的論文；v2 改成可適用各種主題：

- **多分組方案**：報告頁可複選分組方案，每個方案各產出一套「各組結果＋組間比對」。
  分組方案來源是主要分組欄位＋每一個背景欄位（例如同時勾「職級」和「工作年資」，
  就同時得到職級分群報告和年資分群報告，不用分兩次跑）。
- **衍生分組規則**：在後台「研究設定」可為任一欄位定義合併／二分規則，
  例如把年資「5~10年、10~15年、15~20年」併成「年資20年以下」，
  把職級「組長、課長、副理級以上」併成「中階職級以上」。
  填答時仍收原始選項，分析時才映射；對不上任何規則的會標示「未歸類」，
  避免靜默漏算。SMT 範本已內建這兩條規則。
- **動態數量**：構面數、子構面數不再假設 4×4。個人預覽的「幾項排行」「幾張矩陣」、
  示範資料、成對比較題數都依目前架構動態計算；示範資料改依目前架構產生，
  主構面少於 3 項時會說明無法示範無效筆數（因為一致性恆為 0）。
- **後台可編背景欄位與構面增刪**：背景欄位（代碼、名稱、選項）可在後台新增／刪除，
  主構面也可新增／刪除，不用手改 `config.js` 也能換主題；正式部署仍以後台
  「下載新的 config.js」覆蓋為準。
- **構面與指標定義**：每個構面可填 `desc`，每個子構面可填與 `items` 一一對應的
  `itemDescs`。問卷成對比較時會顯示定義，報告最後附錄會列出定義表。
- **彙總方法可選**：報告頁可選「算術平均」（這兩篇論文做法，預設）或
  「幾何平均（先取幾何平均再正規化）」。注意：這裡的幾何平均是「個人權重」的
  幾何平均，不是「判斷值」的幾何平均，兩種做法在文獻中都有，報告會明寫用的是哪一種。
- **整體層級一致性 C.R.H.（可選）**：勾選後，個人預覽與主構面逐人表會另列 C.R.H.，
  定義為 C.I.H.／R.I.H.，其中 C.I.H.＝C.I.(主構面)＋Σ主構面權重×C.I.(子構面)，
  R.I.H. 同理以 R.I. 計算，門檻為 C.R.H. ＜ 0.1。C.R.H. 只是補充指標，
  有效判定仍以逐矩陣 C.R. ≦ 0.1 為準。
- **SMT 生產效率範本**：後台「研究設定」新增「載入 SMT 生產效率範本」，
  一鍵載入第二篇論文的 4 構面 × 16 子構面、定義、職級／年資／學歷背景欄位，
  以及年資二分、職級二分兩條衍生分組規則；主要分組留空，改用背景欄位分組。

不適用範圍仍不變：本系統是「準則排序型」AHP（目標 → 構面 → 子構面），
不含替代方案層；需要方案評選、三層以上層級、模糊 AHP 或 ANP 時需另外擴充。

## 九、通用版（v3）功能開關

v3 在 v2 之上加了兩個「研究層級開關」，存在 `config.js` 的 `features` 裡，
也可在後台「研究設定」勾選。預設兩個都關，行為與 v2 完全相同；
只在研究者需要時才打開，同一套網站就能按主題切換，不用為不同論文各做一版。

- **開啟相依修正（關聯性 AHP，第二階段）**：打開後，問卷在第一階段成對比較之後，
  多一節「第二階段：因子相依比較」。研究者在後台「研究設定 → 相依關係」
  為每個構面定義相依列：選一個基準因子，並勾選要一起比較的因子
  （必須包含基準因子本身）。第二階段量尺只用 1、3、5、7、9，不用中間值 2、4、6、8，
  且題意是「影響力」而非「重要性」：選左方表示左項對基準因子的影響較大。
  計算做法（對照第三篇論文式 4-1～4-3）：先以第二階段成對比較算出影響權重，
  把它填進該構面的相依矩陣中「基準因子那一欄」，沒有相依項目的欄保持單位向量，
  再以「修正後區域權重 ＝ 相依矩陣 × 原始區域權重」算出修正權重，
  最後正規化。報告會同時列出未相依與相依修正後兩套結果與前後比較表（論文表 4-6 格式），
  並列出每位受訪者的相依矩陣 C.I.／C.R.；相依彙總只納入相依矩陣全數通過（C.R. ≦ 0.1）
  且有第二階段資料的問卷。相依修正目前只做「整體」彙總，不做分組相依彙總；
  分組報告仍為未相依結果。開關中途打開後才收的問卷才有第二階段資料，
  之前收的舊問卷（無 `dependencies` 欄位）會自動排除在相依彙總之外，
  但仍納入未相依分析，不會被整個丟掉。
- **開啟方案／客戶評分**：打開後，後台多一個「方案／客戶評分」頁，
  研究者為每位客戶／方案輸入每因子 1–5 分。報告產生時以最終全域權重
  （相依開啟且有相依通過資料時用相依修正後權重，否則用未相依權重）
  算加權總分（Σ 權重 × 評分）與排序。評分表只存在研究者瀏覽器的 localStorage，
  不寫進填答者的問卷紀錄與 Sheets 填答表；報告 HTML 下載後會把算好的評分結果一併帶走。
  評分未填滿或超出 1–5 分的客戶／方案會列出提醒並排除在排序之外。
- **兩個開關獨立**：只開評分不開相依，評分就用未相依權重算；
  只開相依不開評分，就只出相依前後比較表，不評客戶／方案。
- **汽車零件重要客戶範本**：後台「研究設定」新增「載入汽車零件重要客戶範本」，
  一鍵載入第三篇論文的 5 構面 × 16 因子（數量不均 4／3／3／3／3）、定義、
  任職部門／職等／工作年資背景欄位、5 列相依關係（技術能力 2 列、互動與配合度 1 列、
  財務管理 2 列），並同時開啟兩個開關與範例評分 A／B／C（論文表 4-8 分數）。
  範例評分載入後請先在評分頁確認，再改成自己的客戶／方案。
  注意：範本的構面／因子適當性篩選（專家勾適當／不適當）不在網站內，
  須先在外部完成再定架構。

v3 仍不適用：三層以上層級、模糊 AHP、ANP，以及構面間的跨構面相依
（本系統的相依只在同一構面內）。

## 十一、多研究（v3.5）：一個網站，多位研究者各自收案

一個部署就是一個研究的日子結束了。v3.5 讓多位研究者共用同一個網站，
每人有自己的研究題目、自己的試算表、自己的後台密碼，資料互不干擾。

### 連結格式

- 預設研究（config.js 的那一份）：`https://ahp-adm.pages.dev/`（不帶參數，行為與 v3.4 相同）
- 已登記的研究：`https://ahp-adm.pages.dev/?s=代號`，例如 `?s=smt`、`?s=auto-parts`
- 未登記的題目檔：`https://ahp-adm.pages.dev/?config=題目檔網址`（題目檔須允許跨網域讀取，見下）

頁面上方會顯示目前研究與研究切換列；代號打錯、題目檔讀不到或格式有誤時，
會顯示原因（包含格式錯誤的行號）與已登記的研究清單，不會靜悄悄開成別的研究。

### 開一個新研究的流程（管理者做一次，約 10 分鐘）

1. **研究者準備試算表**：在自己的 Google Drive 新建試算表，貼上
   `apps-script/Code.gs`，部署為網頁應用程式（執行身分「我」、存取權「任何人」），
   把 `/exec` 結尾的網址交給管理者。試算表不用開共用，填答者也不需 Google 帳號。
2. **管理者寫題目檔**：複製 `studies/template.txt` 改成新檔（例如 `studies/xxx.txt`），
   填研究標題、後台密碼、Apps Script 網址、構面與指標、背景欄位（格式見下一節）。
3. **登記**：在 `config.js` 的 `studies` 加一筆：`'xxx': { url: 'studies/xxx.txt', title: '研究名稱' }`。
4. **推上 GitHub**：Cloudflare Pages 自動部署後，把 `?s=xxx` 連結交給研究者發問卷。

### 題目檔（.txt）格式

純文字、UTF-8，請用記事本或 VS Code 編輯，不要用 Word。全形半形標點都可
（`：`與 `:`、`，`與 `,`、`→` 與 `->` 都認得）；`#` 開頭是註解行。
完整範例見 `studies/template.txt`，三份真實題目（特教、SMT、汽車零件）在同資料夾。

```
研究標題：……                    # 必填
研究副標題：層級分析法（AHP）問卷
後台密碼：……                    # 必填，跟著題目走，每個研究各自一組
Apps Script 網址：https://script.google.com/macros/s/……/exec
主要分組：任教班別              # 留空表示不用主要分組，改用背景欄位分組
分組選項：集中式特教班, 不分類資源班
相依修正：關                    # 開／關
方案評分：關                    # 開／關

[問卷說明]                      # 可省略；寫了就顯示在填答頁標題下方，空行分段
親愛的老師您好：
首先，誠摯感謝您撥冗填寫本問卷……

[背景欄位]
性別：男, 女
服務年資：10 年以下, 11~20 年, 21 年以上

[構面] 教師個人層面
定義：教師個人的專業知識、技術能力及態度是影響其是否使用資訊科技的重要因素。
科技知識與技能：教師對資訊科技及其在特殊教育中的應用知識與技能。
態度與信念：教師對於資訊科技融入教學的信心和正面態度。

[分組規則]                      # 可省略；把原始選項合併成衍生組
服務年資：10 年以下, 11~20 年 → 年資20年以下
服務年資：21 年以上 → 年資20年以上

[相依關係]                      # 只有開啟「相依修正：開」時才需要
技術能力 / 對供應商製程了解程度：對供應商製程了解程度, 客戶設計規範的完整性
```

- 至少 2 個構面，每個構面至少 2 個指標；指標後面的「：說明」可省略。
- 背景欄位代碼由程式依順序編為 bg1、bg2……：**收案後不要中途調整欄位順序**，
  否則舊資料的欄位會對不上。分組規則用欄位「名稱」指稱欄位（或用 `bg1`、`group`）。
- 格式寫錯時網站會直接報出錯的行號與原因；也可用 Node 先檢查：
  `node -e "var S=require('./assets/studyTxt.js');var r=S.parse(require('fs').readFileSync('studies/xxx.txt','utf8'));console.log(r.ok? 'OK': r.errors)"`。

### 資料隔離與注意事項

- **試算表**：每個研究用自己的試算表＋自己的 Apps Script，寫入與讀取都只走
  該研究的網址；不同研究的資料不會出現在對方的後台。
- **本機紀錄**：填答者瀏覽器的 localStorage、後台本機設定覆寫、評分表，
  都按研究代號分開存（預設研究沿用 v3.4 以前的鍵，舊資料不受影響）。
- **後台密碼**：寫在題目檔裡，看得到檔案的人就看得到密碼，只防誤觸；
  題目檔放在公開 repo 時請一律匿名填答，不要收可識別個人的資料。
  刪除 Sheet 資料仍需 Apps Script 指令碼屬性 ADMIN_CODE 與後台密碼同值。
- **題目檔位置**：放 repo 的 `studies/` 最穩；放外部網址時須是 GitHub raw
  這類允許跨網域讀取（CORS）的位址，**Google 雲端硬碟分享連結讀不到**。
- **後台「研究設定」**：研究模式下改設定、載入範本、下載 config.js 都只影響
  目前這個研究；下載的 config.js 可把該研究部署成獨立的單一研究站。
  後台「研究設定」也可直接改問卷說明（多行文字框），不必手改 txt。
- **問卷說明**：題目檔的 `[問卷說明]` 區寫什麼，填答頁標題下方就顯示什麼
  （空行分段）。不寫此區就不顯示。研究者提供的致謝信、研究目的、指導教授
